FIELD GUIDE / LUA SYSTEMS

      
STORMWORKS: BUILD AND RESCUE / MICROCONTROLLERS

      
Lua from the first wire up.

      
Learn how to start a Lua microcontroller, read and send signals, draw a screen, and grow those pieces into useful systems for boats, planes, and vehicles.
How to use this guide
Try one example at a time in a test vehicle. Connect the channels shown, save, then test in the game.

      
First, know the environment: Stormworks Lua runs inside a microcontroller. The game calls onTick() for logic and onDraw() for a connected monitor. This is different from running a Lua file on your computer.

    

    

      

        
01 / GETTING STARTED
Build a tiny test bench

        

          
In the vehicle editor, add a microcontroller and open its editor. Add a Lua block, open its script, and use the microcontroller’s input and output tabs to create the channels your script needs. Wire a number source to a number input and a number output to a dial or another component. For screen examples, connect a monitor to the microcontroller’s video output.

          
  1. Give channels clear names in the editor, such as Throttle or Speed.
  2. Use the channel number in code: channel 1 is input.getNumber(1).
  3. Press the in-game test or start button and watch the connected output.
  4. Change one thing, test again, and keep a known working copy.

          
Important: Lua reads the numbered channels you configure on the microcontroller. A wire by itself does not tell the script what a value means; your channel layout and code must agree.

        

      

      

        
INTERACTIVE / TEST BENCH
Run Lua in the browser

        

          
Edit the script, set a sample number input, and press Run. The test bench simulates one onTick() and one onDraw(), then shows printed text, output channels, and screen drawing calls.

          

            

            
            
            
This is a browser simulation, not Stormworks itself. Inputs are sample values; screen and output calls are reported as text. The Lua runtime loads from a CDN, so the first run needs an internet connection.

02 / THE SHAPE OF A SCRIPT
Two places your code runs

        
onTick() — logic
Runs repeatedly while the microcontroller is active. Read inputs, calculate values, remember state, and set outputs here.
onDraw() — screen
Runs to draw the monitor image. Get the screen size, choose a color, and draw shapes or text here.

          
function onTick()
    -- Read inputs and update outputs here
end

function onDraw()
    -- Draw the monitor here
end

          
Lua uses -- for comments. Function names and API capitalization matter: write input.getNumber exactly like that. A typo such as input.getnumber will not call the same function.

        

      

      

        
03 / EASY TO HARD
Build up in small steps

        

          
EASY / 01
Pass a signal through
Set up number input channel 1 and number output channel 1. Connect a number source, then check that the output follows it.
function onTick()
    local value = input.getNumber(1)
    output.setNumber(1, value)
end
Learn: local stores a value for this function call. The number inside parentheses is the channel.

          
EASY / 02
Make a simple switch
Set up boolean input channel 1 and boolean output channel 1. A boolean is either true or false.
function onTick()
    local switchOn = input.getBool(1)
    output.setBool(1, switchOn)
end
To invert it, send not switchOn to the output. Use booleans for on/off signals and numbers for measurements.

          
MEDIUM / 03
Keep a value in a safe range
Read a number from channel 1, limit it between 0 and 1, and write it to output channel 1. This is useful when a control should never go below zero or above full scale.
function onTick()
    local value = input.getNumber(1)
    value = math.max(0, math.min(1, value))
    output.setNumber(1, value)
end
The inner math.min sets the upper limit; math.max sets the lower limit.

          
MEDIUM / 04
Draw a basic instrument
Connect a monitor. This reads a number input, shows it as text, and draws a bar for values from 0 to 1.
function onDraw()
    local w = screen.getWidth()
    local h = screen.getHeight()
    local value = math.max(0, math.min(1, input.getNumber(1)))

    screen.setColor(20, 30, 20)
    screen.drawClear()
    screen.setColor(220, 220, 180)
    screen.drawText(2, 2, "LEVEL")
    screen.drawRect(2, 14, w - 5, 6)
    screen.drawRectF(3, 15, (w - 7) * value, 4)
    screen.drawText(2, 24, string.format("%d%%", value * 100))
end
Screen coordinates start at the upper-left: x increases to the right and y increases downward. Keep text and shapes inside the monitor’s width and height.

          
HARD / 05
Make a latched toggle
A push button only stays true while pressed. A latch remembers the state after you release it. Set up boolean input channel 1 and output channel 1, and wire a momentary button to the input.
local isOn = false
local wasPressed = false

function onTick()
    local pressed = input.getBool(1)

    if pressed and not wasPressed then
        isOn = not isOn
    end

    wasPressed = pressed
    output.setBool(1, isOn)
end
wasPressed remembers last tick’s input. The state changes only on the transition from released to pressed, so holding the button does not toggle every tick.

        

      

      

        
04 / WHEN IT BREAKS
Find the problem

        
Nothing changes? Confirm the microcontroller is active, wires reach the right input/output nodes, and the channel numbers match.
The screen is blank? Check the video connection and that code is inside function onDraw(). Try drawing one text label first.
A value is always zero? Check that the source is connected to the right numbered input and uses the expected signal type: number or boolean.
Code stops working after an edit? Check spelling, capitalization, and matching end statements. Temporarily remove recent changes until the last working version runs.
Screen elements are cut off? Use screen.getWidth() and screen.getHeight() rather than assuming every monitor has identical dimensions.
Debugging habit: Test one input and one output first. Add calculations only after you can prove the signal reaches the script.

      

      

        
05 / KEEP LEARNING
Turn examples into systems

        
Once the basics work, try these in order: average a noisy sensor over several ticks, convert a compass reading into a heading display, add alarms with boolean outputs, then draw a multi-instrument dashboard. For bigger scripts, split repeated work into functions and keep related values in tables.
Change one part at a time and test the vehicle after each change. When a script behaves strangely, write down the channel, expected value, and actual value; that makes the bug much easier to locate.
API reference: Stormworks Wiki — Exploring the Lua API for available functions and examples.
